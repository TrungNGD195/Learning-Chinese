# Step 6.10 — Citations

## Goal

Add deterministic citation handling to the completed RAG pipeline so generated answers can reference only sources that were actually selected into the current prompt, survive page reloads, support both internal and external evidence, and remain safe for frontend rendering.

Core flow:

```text
PromptContextBuilder
├── S1
├── S2
└── source_map
↓
LLM
└── answer with [S1] / [S2]
↓
CitationValidator
├── syntax validation
├── source-label validation
└── provenance resolution
↓
atomic persistence
├── Message content
├── MessageRetrieval
├── MessageCitation
└── Assistant COMPLETED
```

Step 6.10 does not evaluate semantic entailment between a claim and a source. Citation correctness/coverage quality belongs to Phase 7.

---

# Citation Syntax

V0 supports exact citation markers:

```text
[S1]
[S2]
[S12]
```

Multiple sources:

```text
[S1][S3]
```

Do not support alternate syntaxes in V0 such as:

```text
(Source 1)
[S1,S2]
[^1]
(1)
[ S1 ]
```

Citation markers should appear as plain text tokens, outside Markdown links and code blocks.

---

# Source Labels Are Message-local

`S1..Sn` are local to one assistant generation/message.

Example:

```text
Assistant Message A:
S1 = Lesson chunk A

Assistant Message B:
S1 = External URL B
```

This is valid.

Never treat `S1` as a global source ID.

---

# Model Must Not Invent Provenance

The LLM may emit only citation labels:

```text
[S1]
[S2]
...
```

It must not generate trusted source metadata such as:

```text
URL
page number
document title
database identity
```

Backend provenance comes only from:

```text
PromptPackage.source_map
```

Flow:

```text
answer contains [S2]
↓
source_map["S2"]
↓
trusted runtime provenance
↓
MessageCitation
```

Do not parse provenance from model prose.

---

# Citation Prompt Instructions

Extend system instructions with an equivalent rule set:

```text
Use only the provided source labels such as [S1], [S2], ...
Cite grounded factual/lesson claims using those labels.
Do not invent source labels.
Do not invent URLs, titles, page numbers, or bibliographic details.
Conversation history is conversational context, not a citation source.
```

Place citations immediately after the supported claim or sentence where practical.

---

# Citation Requirement

For an LLM-generated evidence-based RAG answer:

```text
at least one valid citation is required
```

If no citation marker is present:

```text
CITATION_MISSING
```

Exception:

```text
Step 6.8 deterministic no-evidence refusal
```

This path does not call the LLM and returns:

```text
citations=[]
Assistant status=COMPLETED
```

---

# Conversation Memory Is Not Citation Evidence

Step 6.9 memory must never receive `S1..Sn` labels.

Conversation history is context only.

Do not allow previous assistant responses or previous user messages to become current citation sources.

---

# Historical Citation Marker Isolation

Previous assistant messages may already contain markers such as:

```text
[S1]
```

Because source labels are message-local, those historical labels are unsafe in the next prompt.

When serializing prior assistant messages into `ConversationMemory`, strip system-generated historical citation markers matching the supported citation syntax.

Example:

Stored historical content:

```text
“了 thường ... [S1]”
```

LLM-visible memory:

```text
“了 thường ...”
```

Do not modify the stored historical Message.

Do not strip user-authored text by default.

Only sanitize historical assistant citation markers in memory serialization.

---

# CitationValidator

Create a dedicated component equivalent to:

```text
CitationValidator
```

Input:

```text
generated_text
current source_map
citation_required
```

Output:

```text
CitationValidationResult
```

Do not put citation parsing or validation inside `LLMProvider`.

---

# Validation Flow

Equivalent:

```text
generated answer
↓
detect citation-like malformed tokens
↓
parse exact [S<number>] markers
↓
extract cited labels
↓
validate each label against current source_map
↓
resolve provenance
↓
ValidatedCitation[]
```

Do not guess or repair unknown labels.

---

# Strict Parsing Rules

Examples:

```text
[S1]      → valid
[S12]     → valid
S1        → not a citation
[ S1 ]    → malformed
[S1,S2]   → malformed
[SX]      → malformed
[S0]      → malformed unless source_map explicitly defines S0 (V0 should not)
```

Prefer labels generated by Step 6.6 as:

```text
S1..Sn
```

with positive integers.

Malformed citation-like tokens should produce:

```text
CITATION_FORMAT_INVALID
```

when detectable.

---

# Unknown Labels

If current source map contains:

```text
S1
S2
S3
```

and the answer contains:

```text
[S9]
```

return:

```text
CITATION_UNKNOWN_SOURCE
```

Do not:

```text
map S9 to nearest source
replace with S1
strip it and continue
```

---

# No Silent Citation Repair

If validation fails:

```text
Assistant → FAILED
```

Do not silently:

```text
remove invalid marker
change marker
rewrite prose
```

Do not call a second LLM just to repair citations in V0.

This preserves the Step 6.8 invariant:

```text
one generation per request
```

---

# Deterministic Validation Scope

Step 6.10 can guarantee:

```text
citation syntax is supported
cited label exists
label belongs to current source_map
source was actually included in current prompt
provenance can be resolved
```

Step 6.10 does not guarantee:

```text
the cited source semantically entails the exact claim
every factual claim is fully cited
citation coverage is optimal
```

Those belong to Phase 7 evaluation.

---

# CitationValidationResult

Logical runtime contract:

```text
CitationValidationResult
├── text
├── cited_labels[]
├── citations[]
├── citation_count
├── valid
└── error_code?
```

Keep the original generated text unchanged when validation succeeds.

---

# Duplicate Citation Occurrences

Example:

```text
Sentence A. [S1]
Sentence B. [S1]
```

Both occurrences are valid.

Runtime may count:

```text
citation_occurrence_count = 2
```

Persistence requires only one `MessageCitation` source row for `S1`.

---

# MessageCitation Persistence

Citations must persist with the assistant Message.

Runtime `source_map` alone is insufficient because it disappears after the request.

Create:

```text
Message
1 ─── N MessageCitation
```

Only assistant messages need citation rows.

---

# Unified Internal + External Citation Model

Support:

```text
source_kind = INTERNAL_CHUNK
source_kind = EXTERNAL_URL
```

in one `MessageCitation` model.

Logical fields:

```text
MessageCitation
├── id UUID
├── message_id
├── source_label
├── source_kind
├── chunk_id nullable
├── title
├── url nullable
├── domain nullable
├── source_type nullable
├── locator JSONB nullable
├── metadata JSONB nullable
└── created_at
```

Unique constraint:

```text
UNIQUE(message_id, source_label)
```

Follow existing project naming conventions if equivalents already exist.

---

# Citation Snapshot

Persist display-safe provenance as a snapshot at generation time.

Reason:

Internal source metadata may later change, be superseded, or be deleted.

Historical assistant citations should remain understandable.

Snapshot may include:

```text
title
section
page/locator
lesson metadata
domain
url
source type
```

Do not automatically update historical citation snapshots when live source metadata changes.

---

# Internal Chunk FK

For internal citations:

```text
chunk_id nullable FK
```

Preferred delete behavior:

```text
ON DELETE SET NULL
```

Do not cascade-delete historical citation rows when a Chunk disappears.

If the Chunk is later removed:

```text
MessageCitation remains
snapshot remains
chunk_id becomes NULL
```

---

# Message Delete Behavior

If the parent assistant Message is hard-deleted:

```text
MessageCitation → ON DELETE CASCADE
```

Citation rows do not have independent meaning without the assistant Message.

---

# Internal Learner-facing Metadata

For Lesson citations, expose only display-safe fields such as:

```text
label
source_kind
source_type
title
hsk_level optional
lesson_title optional
content_type optional
section optional
locator/display info optional
```

For Document citations:

```text
label
title
section optional
page_number/locator optional
```

Do not expose:

```text
database UUIDs
storage keys
raw filesystem paths
admin-only metadata
retrieval scores
rerank scores
```

---

# Raw Document Access

A citation does not automatically grant permission to download or view the original raw document.

Source-file access remains an authorization concern outside Step 6.10.

Do not attach raw internal file URLs directly to learner citations by default.

---

# External Citation Persistence

External citation snapshot should include at least:

```text
label
source_kind=EXTERNAL_URL
title
url
domain
```

Do not persist full external snippets solely for citation display unless there is a separate audit requirement.

---

# External URL Validation

Before persisting/rendering an external citation, validate the URL from `source_map`.

Required:

```text
scheme = https
hostname exists
hostname ∈ configured trusted allowlist
```

Reject unsafe schemes:

```text
javascript:
data:
file:
```

The URL must come from trusted runtime provenance, never from generated model prose.

If invalid:

```text
CITATION_EXTERNAL_URL_INVALID
```

---

# Model-generated Links

Prompt the model not to invent clickable external URLs.

The generated answer should cite:

```text
[S1]
```

Frontend resolves the real validated URL from citation payload.

Do not treat arbitrary Markdown links in model output as trusted citations.

---

# Persist Only Cited Sources

If source map contains:

```text
S1 S2 S3 S4 S5
```

and answer uses only:

```text
S1 S3
```

persist only:

```text
MessageCitation(S1)
MessageCitation(S3)
```

Do not persist all available prompt sources as citations.

Broader internal retrieval trace remains in `MessageRetrieval`.

---

# Step 6.8 Finalization Update

Extend successful RAG completion:

```text
LLM Generation
↓
CitationValidator
↓
valid?
├── no
│   └── Assistant FAILED
└── yes
    ↓
    BEGIN
    ├── persist Assistant content
    ├── persist MessageRetrieval when internal
    ├── persist MessageCitation
    └── PENDING → COMPLETED
    COMMIT
```

Do not mark the assistant Message `COMPLETED` before citation validation succeeds.

---

# Atomic Completion

Assistant content, retrieval trace, citations, and status transition must be finalized atomically where applicable.

Do not allow:

```text
Assistant COMPLETED
+
citation insert failed
```

If the completion transaction fails:

```text
ROLLBACK
```

The message must not remain as a successful uncited answer.

---

# Citation Validation Failure

On citation validation failure:

```text
Assistant PENDING
→ FAILED
```

Store/use a normalized error state according to the existing message failure model.

Do not expose the raw invalid/uncited generated answer to the learner as a completed response.

---

# Error Contract

Use normalized errors equivalent to:

```text
CITATION_MISSING
CITATION_FORMAT_INVALID
CITATION_UNKNOWN_SOURCE
CITATION_SOURCE_RESOLUTION_FAILED
CITATION_EXTERNAL_URL_INVALID
CITATION_VALIDATION_FAILED
```

Reuse existing project error conventions.

Do not expose raw parser/database/provider exceptions.

---

# API Response Contract

Extend assistant message response:

```text
AssistantMessageResponse
├── id
├── role
├── content
├── status
└── citations[]
```

User messages return:

```text
citations=[]
```

or omit citations only if that matches the existing API consistency rules. Prefer a consistent array.

Learner-facing contract equivalent to:

```text
CitationResponse

├── title
├── source_type?
├── section?
├── page_number?
```

# Frontend Rendering

The assistant content may contain:

```text
"... [S1]"
```

with response metadata:

```text

S1 → CitationResponse(...)
```

Frontend should render `[S1]` as a safe citation chip/reference.

Do not trust arbitrary model-generated URLs.

# Historical Citation Stability

If an internal source is later deleted:

```text

```

If live `chunk_id` becomes unavailable:

```text

```

but learner can still see historical display provenance.

If an external page later changes/disappears, preserve the original:

```text

```

Step 6.10 does not guarantee external pages remain reachable forever.

# Migration

Reconcile the canonical `MessageCitation` schema through a **forward Alembic migration**.

Phase 2 defines the target citation persistence contract. If the base `message_citations` table already exists from earlier migrations, alter/reconcile it as needed; **do not create a second incompatible citation table or parallel persistence model**. If implementation sequencing means the table has not yet been materialized, create it once using the canonical schema.

The resulting schema must include:

```text
UUID primary key
message_id FK
source_label
source_kind
chunk_id nullable FK
display snapshot fields
JSONB locator/metadata where appropriate
created_at
UNIQUE(message_id, source_label)
```

Foreign key behavior:

```text
message_id → ON DELETE CASCADE
chunk_id   → ON DELETE SET NULL
```

Inspect existing naming/type conventions before implementing.

# Acceptance Criteria

- [ ] Citation syntax uses exact `[S<number>]` markers.
- [ ] Source labels are local to one assistant message.
- [ ] LLM does not provide trusted provenance metadata.
- [ ] Backend resolves citations only from current `source_map`.
- [ ] Citation prompt rules prohibit invented labels/URLs.
- [ ] Evidence-based generated answers require at least one valid citation.
- [ ] Deterministic no-evidence refusal returns no citations and remains valid.
- [ ] Conversation memory is never a citation source.
- [ ] Historical assistant citation markers are stripped only during memory serialization.
- [ ] `CitationValidator` is separate from `LLMProvider`.
- [ ] Strict parsing rejects malformed citation syntax.
- [ ] Unknown labels fail explicitly.
- [ ] Invalid citations are not silently stripped or repaired.
- [ ] No second LLM citation-repair call is introduced.
- [ ] Validation checks syntax/label/provenance only, not semantic entailment.
- [ ] Duplicate occurrences map to one persisted source row per label.
- [ ] `MessageCitation` persists citations with assistant Messages.
- [ ] Internal and external sources use one citation model.
- [ ] Citation display provenance is snapshotted.
- [ ] Internal `chunk_id` uses nullable FK with `ON DELETE SET NULL`.
- [ ] Parent Message delete cascades citation rows.
- [ ] Historical snapshots do not change when live metadata changes.
- [ ] Learner API does not expose internal storage/DB metadata.
- [ ] Raw-document access is not implied by citation.
- [ ] External URLs come only from source_map.
- [ ] External URLs must be trusted HTTPS URLs.
- [ ] Unsafe URL schemes are rejected.
- [ ] Only actually cited labels are persisted.
- [ ] Assistant content + retrieval trace + citations + COMPLETED transition finalize atomically.
- [ ] Citation validation failure results in FAILED assistant status.
- [ ] Assistant API returns `citations[]`.
- [ ] Frontend can render `[S1]` using backend citation metadata.
- [ ] Historical citation rendering survives page reload/source deletion.
- [ ] Phase 7 can evaluate citation correctness and coverage without changing the basic persistence contract.
